# Hardware

## What you need

- **Sipeed Tang Nano 20K.**
- **HDMI display or capture card:** 720×480p input.
- **Optional:** a 1.44" 128×128 ST7735S SPI LCD module (the common red board with SCL/SDA/RES/DC/CS/BL pins).
- **Optional:** a DualShock 2 and the Sipeed DualShock adapter, and/or 8 push buttons.
- **Optional:** a microSD card (FAT32 or exFAT) in the board's TF slot, a piezo buzzer or a small speaker.

## Pin map

All signals are on the two header rows of the Tang Nano 20K. The constraints are in `rtl/board/tangnano20k.cst`.

### Buttons

Each button connects its pin to **GND**; the FPGA's internal pull-ups are enabled, so no resistors are needed. The inputs are synchronized and debounced (2 ms sampling, two equal samples).

| Button | Pin | | Button | Pin |
|---|---|---|---|---|
| Up | 25 | | A | 29 |
| Down | 26 | | B | 30 |
| Left | 27 | | Select | 31 |
| Right | 28 | | Start | 77 |

Select + Start together opens the menu, as on the DualShock.

### ST7735S LCD

| LCD pin | FPGA pin | Notes |
|---|---|---|
| VCC | 3V3 | |
| GND | GND | |
| SCL / SCK | 73 | 16.875 MHz (clk_sys / 2) |
| SDA / MOSI | 74 | |
| RES / RST | 71 | reset is generated by the FPGA after power-up |
| DC / A0 | 72 | |
| CS | 53 | |
| BL / LED | 52 | PWM (~8 kHz) set by LCD Backlight; low when the LCD is off |

**If the picture is shifted, mirrored or has swapped colors:** 1.44" modules differ, and the driver has parameters for that in `rtl/top/gbc_top.sv`:

```verilog
lcd_st7735 #(.CLK_HZ(33_750_000)) u_lcd (...);
//  parameters (defaults):
//    SPI_HALF = 1       SCL half period in clk cycles; 2 = 8.4 MHz if long wires cause errors
//    MADCTL   = 8'hC8   MY|MX|BGR. Bit 3 (BGR) swaps red/blue; MX/MY (bits 6/7) mirror, MV (bit 5) rotates
//    X_OFS    = 2       column offset of the 128x128 window in the 132x162 panel RAM
//    Y_OFS    = 3       row offset (some modules need 1 or 32)
//    INVERT   = 0       1 sends INVON (some IPS variants show inverted colors otherwise)
```

**How the LCD output works:**
- The pixel stream is the same one that feeds the HDMI framebuffer. It is converted to RGB with the same palette and color-correction settings, then scaled.
- The image is stored in a 128×128 × 13-bit BSRAM frame (R4 G5 B4). It is sent to the panel continuously: 16384 pixels × 16 bit at 16.9 MHz, about 64 fps. The panel has no tearing-effect pin wired, so fast scrolling can show a tear line.
- *Fit*: 2-tap filter in both directions (5 → 4 pixels): 160×144 becomes 128×115, centered with black bars.
- *Crop*: the center 128×128 (columns 16–143, rows 8–135) at 1:1.

### microSD card

The on-board TF slot is used in SPI mode: CLK 83, CMD/MOSI 82, DAT0/MISO 84, DAT3/CS 81 (DAT1 / DAT2 held high). The clock is 260 kHz during initialisation and 16.9 MHz afterwards. SDSC, SDHC and SDXC cards work; the file system can be FAT12/16/32 or exFAT.

### Cartridge flash (W25Qxx)

An external SPI NOR flash module (W25Q16 to W25Q128, or a bare chip) works as a game cartridge.

| Chip pin | FPGA pin |
|---|---|
| CS (1) | 51 |
| DO / MISO (2) | 49 |
| WP (3) | 3V3 |
| GND (4) | GND |
| DI / MOSI (5) | 55 |
| CLK (6) | 48 |
| HOLD (7) | 3V3 |
| VCC (8) | 3V3 |

The clock is 8.4 MHz, so short jumper wires are fine.

### Original cartridges

The same four pins can instead drive a reader for original Game Boy / GBC cartridges: four 74HCT595 and a 74LV165, no microcontroller. See [cart_reader.md](cart_reader.md). The menu probes for a W25Q first and for the reader when no flash answers.

### Buzzer / speaker

| Pin | Signal |
|---|---|
| 76 | audio + (1-bit sigma-delta at 33.75 MHz) |
| 75 | audio − (the inverted signal) |

- **Piezo buzzer:** connect it between pins 76 and 75; the push-pull drive doubles the swing.
- **Small speaker (8 Ω):** do not connect it directly. Use a transistor or a small class-D amplifier on pin 76, ideally after an RC low-pass (for example 1 kΩ + 10 nF).

The output is the mono mix after the Volume setting, with the DC level removed and Speaker Boost applied (x4 by default), muted in the menu, and held low when Speaker is off.

### Link port (cable to an original Game Boy / GBC)

The link port connects to a real Game Boy, Game Boy Color, Game Boy Pocket or GBA (in GB/GBC mode) with an ordinary link cable, and to a Game Boy Printer. Turn it on with **System → Link Port**.

| Signal | FPGA pin | Direction |
|---|---|---|
| SC (clock) | 41 | both: we drive it when the game uses the internal clock |
| SI (data in) | 42 | in |
| SO (data out) | 56 | out |
| GND | GND | |

**Level shifter.** Use one on all three lines: the Game Boy's link port is 5 V and the FPGA pins are 3.3 V only. A 4-channel BSS138 module or a TXS0104 works:
- LV → Tang **3V3**, HV → Tang **5V**, GND to both;
- LV1/2/3 ↔ pins 41/42/56, HV1/2/3 ↔ SC/SI/SO of the cable.

**The cable crosses SI and SO.** The easiest way is to build a socket that copies the console's own port: then an unmodified cable plugs in, and the cable does the crossing.

| Socket pin (looking into the console port) | Signal | Goes to |
|---|---|---|
| 1 | VCC | not connected |
| 2 | SO | HV of pin 56 |
| 3 | SI | HV of pin 42 |
| 4 | SD | not connected |
| 5 | SC | HV of pin 41 |
| 6 | GND | GND |

**With a cut cable**, identify the wires with a multimeter against the plug that stays on the console's side:
- that plug's pin 2 (the console's SO) → our SI (42);
- its pin 3 (the console's SI) → our SO (56);
- its pin 5 → SC (41), its pin 6 → GND.

Most cables leave pins 1 and 4 unwired.

**Speed.** The core's serial port runs at the real rates: 8 kHz with the external clock, and up to 512 kHz with the GBC double-speed clock. Keep the wires under ~30 cm.

**What to play.** Trading and battles (Pokémon), Tetris and F-1 Race two-player and Printer games all work. Both consoles must run compatible games, as with two real Game Boys.

### Bluetooth module (ZS-040 / HC-05 / HC-06)

The link-port pins can carry a Bluetooth serial module instead of the cable: Menu › Controls › Link Port › Bluetooth (bitstream 1.7). The Android app then connects without a USB cable: remote buttons, settings, the log and a slow live screen.

| Module | Tang Nano 20K |
|---|---|
| VCC | 5 V |
| GND | GND |
| TXD | pin 42 (link SI) |
| RXD | pin 56 (link SO) |

- The ZS-040 board has a 3.3 V regulator and 3.3 V logic, so no level shifter is needed.
- Set the module to 115200 baud once:
  - HC-05: hold the button while powering up, then send `AT+UART=115200,0,0`.
  - HC-06: send `AT+BAUD8`.
- Pair it in the phone's Bluetooth settings (PIN 1234 or 0000), then in the app: Remote › Connect over Bluetooth.
- **Speed:** the module stays at 115200. The live screen over Bluetooth is about 1 frame per second and has no sound. Over USB it is about 6 fps, with sound. Installing firmware still needs USB.
- The Game Boy link cable and the printer can't be used while Bluetooth is on: they share the pins.

### Carrier board extras (Menu button, USB power, battery gauge)

Optional; a bare Tang Nano runs without them.

| Signal | FPGA pin | Wiring |
|---|---|---|
| Menu button | 54 | to GND, internal pull-up; same as S1 |
| USB power present | 86 | VBUS through a 10 kΩ / 20 kΩ divider (5 V → 3.3 V), internal pull-down |
| I²C SCL to IP5306-I2C | 15 | 4.7 kΩ pull-up to 3V3 |
| I²C SDA to IP5306-I2C | 16 | 4.7 kΩ pull-up to 3V3 |

The status icons in the menu header come from these pins:
- a battery with its level (from IP5306 register 0x78);
- a plug while USB power is present or the battery is charging;
- a PC while Studio or a script has sent remote commands in the last 15 s.

Pins 15 and 16 are also the board's LED0/LED1, which blink faintly while the gauge is read (every 5 s). Without the pull-ups the bus does not idle high, and the menu shows no battery.

### DualShock 2

Use the Sipeed adapter on pins 17–20, the same as NESTang. These pins are shared with LEDs 2–5. The controller is polled continuously by `rtl/io/dualshock_controller.v`.

| PS2 | Game Boy |
|---|---|
| D-pad | D-pad |
| ○ / △ | A |
| ✕ / □ | B |
| Start / Select | Start / Select |

### Board buttons and LEDs

| | Function |
|---|---|
| S1 (pin 88) | open / close the menu |
| S2 (pin 87) | reset the game |
| S1 held 1 s | HDMI on / off |
| LED0 | lit while a game is loading (only with System → Activity LEDs) |
| LED1 | lit while the menu is open (only with Activity LEDs) |
| RGB LED (WS2812, pin 79) | kept dark |

### USB-UART

The BL616 debugger exposes a serial port (COM*n* on Windows) wired to FPGA pins 70 (RX) and 69 (TX). The design receives 115200 8N1 remote commands on it ([remote.md](remote.md)), and the menu firmware prints its log on TX.
